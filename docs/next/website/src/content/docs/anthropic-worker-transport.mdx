title: Anthropic worker transport
description: Server-owned credentials and fail-closed API accounting infrastructure.
---

The first API-worker slice supplies an internal Unix transport and accounting
service. It does **not** switch subscription workers to the API, add a new worker
kind, or start spending automatically. Worker lifecycle integration, fallback,
and the usage widget are separate work. No advertised client method or frozen
client codec changes in this slice. For the integrated worker lifecycle and
current configuration, see [Anthropic API credit workers](/docs/anthropic-api-workers/).

```toml
[workers]
anthropic_api_key_file = "~/.config/herdr/worker-api-key"
anthropic_api_cap_usd = 200.0
anthropic_api_model = "claude-sonnet-5-5"
```

The key file must be owned by the server's user and have mode `0600`.
An empty path disables API access. Paths must be absolute or start with `~/`;
the server resolves symlinks before installing worker read denials. A configured
file that cannot be resolved prevents new workers from starting, rather than
silently omitting the denial. Do not place credentials in a declarative,
world-readable configuration store.

## Internal service contract

The server calls `AnthropicProxy::open` with the workers configuration and a
persistent SQLite ledger, registers a run and item to obtain an opaque random
bearer token, and owns the socket accept loop. The socket's parent must be
user-owned and private (`0700`); the socket is `0600`. An existing socket path
is never replaced. The ledger belongs in server state outside worker writable
roots. Tokens remain in memory and can be revoked; `kill` disables admission.
The next worker slice must give the API client only its run token and transport
address, never the real API key. This infrastructure does not yet distribute
tokens to workers or publish control methods.

Only `POST /v1/messages` and `POST /v1/messages/count_tokens`, optionally with
exactly `?beta=true`, are accepted. Each proxy admits only its configured
`anthropic_api_model` (default `claude-sonnet-5-5`), validated against the
supported standard Sonnet tariffs. Token counting is authenticated but does not
create billed message rows. Absolute URLs, other query strings, CONNECT,
chunked request bodies, duplicate authentication or length headers, unknown
models, premium service tiers, and server-side tools are refused. Bodies are limited to 150,000 bytes and output to 64,000 tokens.
Only text and ordinary client-tool content are supported. Images, documents,
remote/file sources and thinking replay are refused: their expanded
input cannot safely be reserved from the submitted byte count. Tool schemas
must be inline, without reference expansion. Conservative per-message/tool
framing is reserved too; requests whose input bound reaches 200,000 tokens are
refused to exclude long-context premium pricing. Validated JSON
is re-encoded before forwarding so duplicate keys cannot change upstream model
or token-limit interpretation. The server forces `service_tier = "standard_only"`
rather than allowing the API's default automatic priority-tier selection.
Thinking configuration accepts `disabled`, `enabled` with `budget_tokens`,
`adaptive`, and `between_tools` (with an optional `budget_tokens`). Explicit
budgets must be integer token counts of at least 1,024 and below `max_tokens`.
The proxy preserves the requested type; it does not inject disabled thinking.
`max_tokens` bounds thinking and visible output together, and the full ceiling
is reserved at the output tariff before forwarding. API-reported
`output_tokens`, including billed thinking, determine the settled cost. A
request whose reservation exceeds remaining credit is refused with 402 before
any upstream call. Opaque/summarized thinking replay remains refused because
its expanded input cannot safely be bounded from submitted bytes.
Client authentication and destination headers are discarded; only allowlisted
`anthropic-beta` features are preserved. The server supplies API version, content type
and `x-api-key` to the fixed HTTPS destination `api.anthropic.com`. Curl receives
its configuration through an anonymous pipe, with curlrc, HTTP proxy routing,
redirects, stderr, and core dumps disabled. The server also disables its own core
dumps before reading the credential. Neither credential nor headers are logged.
Refusals name a safe check in the JSON response and server log, along with
normalized method, path, model and upstream status when known. Anthropic JSON
errors expose only `error.type` and `error.message`, not the full response body;
these fields are also logged. HTTP 4xx/5xx statuses are preserved. Local statuses
are 401 for invalid run tokens, 403 for non-allowlisted requests, 402 for credit
caps and 502 for transport or accounting failure. Once SSE
has started, a failure is logged and the stream ends instead of appending an
HTTP response.

Responses stream through without buffering the entire SSE response. Usage is
parsed incrementally; JSON responses are bounded. The ledger records run, item,
model, input/output and cache tokens, and USD cost computed from API usage using
the allowlisted model's standard token prices, including one-hour cache writes.
The Messages API does not return an authoritative dollar cost; Console billing
remains the authority. New models or pricing tiers require an explicit pricing
and allowlist change, not a guessed default.

Admission serializes through the ledger and reserves a conservative input/output
upper bound before any upstream request. A durable pending row precedes network
access. Missing or malformed usage, transport failure, interruption, a client
that disconnects, or an unavailable counter fails closed. A pending request
survives restart and refuses further spend, even with a higher cap. A definite
HTTP 4xx or 5xx rejection before any message response bytes releases its
reservation at zero cost, including when its error JSON is absent or malformed.
A broken transport, malformed 200 response, or SSE error remains uncertain and
keeps the latch. Completed cost also survives restart; there is no timer-based
or automatic billing-cycle reset. Do not delete the ledger to work around a refusal.

## Owner reconciliation

Run `herdr credits status` on the server host as its owner. It reads the local
configured cycle's ledger without reading the API key and prints total recorded
USD, pending count, and entries (id, run, item, model, cost and state). States
are `pending`, `accounted`, or `released`; released entries remain in the ledger.
This is a local owner command, not an advertised remote client method.

Before running `herdr credits release <entry>`, stop the affected worker and
verify through the upstream error or Console that its request consumed no
tokens. Issuing release is the owner's explicit attestation of no usage: it
clears that pending entry at zero cost, reopening admission only if no other
pending entry or cap remains. Never release an active request or an uncertain
request that may have consumed tokens. Release rejects missing and already
settled entries and cannot erase accounted costs. It does not reset the cap or
change the billing cycle.

Offline tests replay Anthropic's documented 400 JSON error shape with pi's
`?beta=true` and allowlisted `anthropic-beta` header intact. The proxy forwards
these unchanged and exposes an upstream beta rejection message; it does not
reject this pi request shape locally. A fake upstream cannot establish whether
Anthropic rejected the real run's model, beta features or balance. The next real
refusal's error type and message provide that evidence; no beta flag is removed
or model changed speculatively.

The default local lifetime ceiling is USD 200; zero disables spending. Keep a
dedicated Anthropic workspace spend limit as the independent upstream ceiling.
The worker shell sandbox continues to deny **all** direct network access,
including Anthropic. Claude file-tool rules, pi's shell profile, and herdr's file
policy deny the configured key, even when it is inside a worker root; directory
and glob reads containing that key are denied too. The API client's access to
the proxy is distinct from its sandboxed tools' network privileges.

Tests use an injected offline upstream and synthetic credentials only. The Unix
socket smoke test also uses an offline upstream; no test calls Anthropic.
